localStorage-Labor

Erst die Theorie lesen, dann im Labor eine Datenbank anlegen und alle CRUD-Schritte ausprobieren.

1. Was ist localStorage?

Ein kleiner Speicher direkt im Browser. Die Daten bleiben erhalten, auch wenn du die Seite schließt oder das Gerät neu startest.

Eckdaten: etwa 5 MB Platz, es lassen sich nur Texte speichern, jede Domain hat ihren eigenen Bereich, und alles bleibt auf diesem Gerät in diesem Browser. Einen Server gibt es nicht.

2. Die fünf Befehle 
localStorage.setItem("name", "Anna");  // schreiben oder überschreiben
localStorage.getItem("name");          // lesen: "Anna" oder null
localStorage.removeItem("name");       // einen Eintrag löschen
localStorage.clear();                  // ALLES löschen (Vorsicht!)
localStorage.key(0);                   // Name des 1. Eintrags
localStorage.length;                   // Anzahl der Einträge

Ein Eintrag besteht immer aus einem Schlüssel (Name) und einem Wert (Text).

3. Nur Text: JSON als Übersetzer

Zahlen, Listen und Objekte muss man vor dem Speichern in Text umwandeln und beim Lesen zurückverwandeln.

const person = { name: "Anna", alter: 31 };
localStorage.setItem("p", JSON.stringify(person));   // Objekt → Text
const zurueck = JSON.parse(localStorage.getItem("p")); // Text → Objekt
console.log(zurueck.alter); // 31
4. Eine „Datenbank“ nachbauen

localStorage kennt keine Tabellen. Du baust sie selbst: Der Schlüssel ist der Tabellenname, der Wert ein JSON-Text mit einer Liste von Datensätzen. Jeder Datensatz bekommt eine eindeutige id.

Schlüssel:  "lab:kontakte"
Wert:       {
  "fields": [{"name":"Name","type":"text"}],
  "rows":   [{"id":"k1x","Name":"Anna"},
             {"id":"k2y","Name":"Ben"}]
}

Im Labor hat jede Datenbank eine Feldliste (fields) und die Datensätze (rows).

5. CRUD: Laden, ändern, speichern

Merksatz: Man ändert nie einen einzelnen Datensatz im Speicher, sondern lädt die ganze Liste, ändert sie und speichert sie zurück.

const db = JSON.parse(localStorage.getItem("lab:kontakte"));

// Create: hinzufügen
db.rows.push({ id: "k3z", Name: "Cem" });

// Read: lesen
const ben = db.rows.find(r => r.id === "k2y");

// Update: ersetzen
const i = db.rows.findIndex(r => r.id === "k2y");
db.rows[i] = { id: "k2y", Name: "Benjamin" };

// Delete: entfernen
db.rows = db.rows.filter(r => r.id !== "k1x");

localStorage.setItem("lab:kontakte", JSON.stringify(db));

Die Datenbank selbst: anlegen mit setItem, umbenennen durch neu speichern und alten Schlüssel mit removeItem löschen, löschen mit removeItem.

6. Stolpersteine

1. getItem liefert null, wenn es den Schlüssel nicht gibt. Prüfe das vor JSON.parse.
2. Ungültiges JSON lässt JSON.parse abstürzen. Nutze try/catch.
3. Wer die Browserdaten löscht, verliert alles. Wichtiges also exportieren.
4. Kein Abgleich zwischen Geräten und Browsern.
5. Keine Passwörter oder private Daten speichern, jedes Skript auf der Seite kann mitlesen.
6. Ist der Speicher voll oder gesperrt (z. B. im privaten Modus), wirft setItem einen Fehler.
